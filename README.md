# autolog-web

Autolog(운행일지) 웹입니다. 화면은 두 가지입니다.

- **폰 확인 화면** `/s/{sessionId}#t={phoneToken}`: 차량 화면의 QR을 스캔하면 열립니다. 확인하지 않은 운행의 목적, 이용자, 비고를 입력해 차량으로 보냅니다.
- **관리자 화면** `/admin`: 차량이 보고한 운행으로 만든 **운행기록부**(국세청 업무용승용차 서식 열 순서)를 봅니다. QR 세션 현황은 보조 메뉴 `/admin/sessions`로 옮겼습니다.

데이터는 모두 [autolog-server](../autolog-server)를 거쳐 오갑니다. 이 앱에는 자체 백엔드가 없습니다.

## 기술 스택

- Next.js 15.5 (App Router), React 19.2, TypeScript 5.9
- UI 라이브러리를 쓰지 않고 전역 CSS(`src/app/globals.css`) 하나로 스타일을 관리합니다.
- 테스트는 Node 내장 `node:test`로 돌립니다. TypeScript는 Node 24의 타입 제거 기능으로 바로 실행합니다.

## 실행

Node.js 22 이상이 필요합니다(v24에서 확인).

```bash
npm install
npm run dev        # 개발 서버 http://0.0.0.0:3000
npm run build      # 프로덕션 빌드
npm start          # 빌드 결과 실행 http://0.0.0.0:3000
npm run lint       # ESLint
npm run typecheck  # tsc --noEmit
npm test           # 단위 테스트(폼 상태, API 클라이언트, 토큰 파싱)
```

`dev`와 `start`는 `-H 0.0.0.0 -p 3000`으로 실행됩니다. 그래서 같은 Wi-Fi에 있는 폰이 `http://{PC의 LAN IP}:3000`으로 접속할 수 있습니다. 서버(autolog-server)도 같은 PC의 4000 포트에서 실행하세요.

### 직접 확인하는 순서

1. autolog-server를 실행합니다(`npm start`, 포트 4000).
2. 이 앱을 실행합니다(`npm run dev`).
3. 차량 대신 curl로 세션을 만듭니다. 방법은 서버 README의 "세션 생성 예시"를 참고하세요. 응답의 `joinUrl`을 폰이나 브라우저로 엽니다.
4. `http://localhost:3000/admin`에서 관리자 키(기본값 `dev-admin`)를 입력해 제출 현황을 확인합니다.

## 환경변수

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `NEXT_PUBLIC_API_URL` | (없음) | API 서버 주소입니다(예: `http://192.168.0.10:4000`). 비워 두면 브라우저가 접속한 호스트의 4000 포트, 즉 `${location.protocol}//${location.hostname}:4000`을 씁니다. |

`NEXT_PUBLIC_*` 값은 **빌드할 때** 번들에 들어갑니다. 값을 바꿨다면 다시 빌드하세요. 예시는 `.env.example`에 있습니다.

## 화면

### `/` 소개

앱을 짧게 소개하고 "차량 화면의 QR을 스캔하세요"라는 안내와 관리자 화면 링크를 보여줍니다.

### `/s/[id]` 운행 확인 (모바일 우선)

- 토큰은 URL 해시 `#t=...`에서만 읽습니다. 해시는 웹 서버로 전송되지 않습니다. API에는 `Authorization: Bearer {token}` 헤더로만 보내고, URL 쿼리에는 절대 넣지 않습니다.
- 운행 카드에는 날짜, 시각(Asia/Seoul), 거리(km), `출발 → 도착`, 추천 목적 배지가 표시됩니다.
  - **목적**: 출퇴근·업무·개인 중 하나를 고르는 3버튼입니다. 추천 목적에는 "추천" 표시가 붙고 처음부터 선택되어 있습니다. 추천이 없으면(미분류) 직접 골라야 보낼 수 있습니다.
  - **이용자**: 세션의 people 중에서 고릅니다. 기본값은 운행에 기록된 이용자(`trip.userId`)입니다.
  - **비고**: 선택 입력이며 최대 200자입니다.
- 이미 보낸 운행(`submittedTripIds`)에는 "보냄" 배지가 붙고 이번 제출에서 빠집니다. "다시 보내기"를 누르거나 목적을 다시 고르면 수정한 내용으로 다시 보낼 수 있습니다.
- 하단의 "N건 차량에 보내기" 버튼을 누르면 제출되고 완료 화면이 나타납니다. 완료 화면에는 "차량이 P 상태일 때 장부에 반영됩니다"라고 안내합니다.
- 운행이 하나도 없으면 "확인할 운행이 없습니다"를 표시합니다.
- 토큰이 없거나 서버가 401·404를 돌려주면 "QR이 만료됐어요. 차량 화면에서 QR을 다시 띄워주세요"를 표시합니다.
- 400 오류가 나면 서버가 보낸 한국어 메시지를 제출 버튼 위에 표시합니다.

### `/admin` 운행기록부

- 차량 선택, 기간(기본: 그 차량의 사업연도, 없으면 이번 달·바로가기 버튼), 상태(전체/미확인/확인/정정), "미확인·누락 행 포함" 토글로 거릅니다.
- 상단에 법인명·사업자등록번호·차종·차량번호·사업연도와 ⑪ 총주행거리, ⑫ 업무용 사용거리, ⑬ 업무사용비율, 미완성·미확인·누락 운행 건수를 보여 줍니다.
- 행: 사용일자, 사용자(부서·성명), 주행 전/후 계기판, 주행거리, 출·퇴근용/일반 업무용, 비고, 상태, 마지막 보고(사유·시각). 필수 값이 비면 빨간 "누락" 표시가 붙습니다.
- 행을 누르면 그 운행의 보고 이력(종료·시동 OFF·확인·정정·재전송)과 정정 이력이 펼쳐집니다.
- "CSV 내려받기", "Excel(XLSX) 내려받기"는 현재 필터 그대로 서버에서 파일을 만듭니다. 관리자 키는 헤더로만 보내고(fetch → Blob) 주소에 넣지 않습니다.

### `/admin/sessions` QR 세션(보조)

- 처음 들어오면 관리자 키를 입력합니다. 키는 `sessionStorage`에 저장되므로 탭을 닫으면 지워집니다. 저장소를 쓸 수 없는 환경이면 메모리에만 둡니다. 키가 틀려 401이 나면 키를 지우고 다시 입력하라고 안내합니다.
- 세션 목록 표에는 생성 시각, 차량번호, 운행 수, 제출 수, 대기 수, 만료 여부가 나오고 5초마다 자동으로 새로고침됩니다.
- 표의 행을 누르면 `/admin/sessions/[id]` 상세 화면으로 갑니다. 상세 화면에서는 운행 목록과 제출 이력(목적, 이용자 이름, 비고, 제출 시각, 차량 반영 여부와 반영 시각)을 볼 수 있습니다. 이 화면도 5초마다 새로고침됩니다.

## 디자인

- 현대 네이비(`#002C5F`), 화이트, 라이트 샌드(`#E4DCD3`)를 쓰는 밝은 테마입니다.
- 버튼은 모서리가 각지고(radius 2px), 터치 영역의 높이는 최소 52px입니다.
- 디자인 시스템 설정 파일(OmD 등)은 이 레포가 아니라 `Goodnight-Camp/.github`에서 관리합니다.

## 구조

```
src/
  app/
    layout.tsx, page.tsx, globals.css
    s/[id]/page.tsx                 폰 확인 화면(클라이언트 컴포넌트)
    admin/page.tsx                  세션 목록
    admin/sessions/[id]/page.tsx    세션 상세
    admin/KeyGate.tsx, useAdmin.ts  관리자 키 입력, 5초 폴링 훅
  lib/
    api.ts          API 클라이언트(베이스 URL 결정, 오류는 ApiError로 통일)
    confirmForm.ts  확인 폼 상태 리듀서와 제출 항목 변환
    format.ts       Asia/Seoul 기준 날짜·시각 포맷, 목적 라벨
    token.ts        해시 토큰 파싱
    types.ts        API 계약 타입
    lib.test.ts     단위 테스트
```
